# FoldPutt 美术提示词、命名与导入规范

更新：2026-09-29。本文件仅交付 prompt、文件名和导入约定；本对话不生图、不创建美术文件、不改业务代码、Xcode 工程或现有 Assets。

来源：`docs/ui-prompt-library.md`、`docs/screens.md`。沿用提示词库中的 Friendly Physics 风格、配色和动效；命名与导出规格是本轮新增交付约定，不是设备硬编码规则。配色变量沿用库所引用的 `specs/theming.md` 设计命名，不重命名 Swift API。

## 1. 使用方法与状态

- 主表为 **14 个界面/状态条目 × 3 态 = 42 条独立英文 prompt**，每条均以 `Generate a UI image:` 开头，可单独复制。星级奖励是结算状态变体；深夜/传机/皮肤仍为来源中标记延后的美术概念，不表示程序已实现。
- 状态完整覆盖 `default`、`aiming`、`charging`、`hole-success`、`star-reward`、`penalty-reset`；不把所有菜单页机械扩成六种对局状态。原文 success 对应 hole-success，星级单列 star-reward；penalty-reset 只表示本图中的回退反馈，不新增失败规则。
- 为生成工具提供目标画幅与实际安全区/保留区遮罩。没遮罩时先出保守留白概念，不宣称硬件像素精确适配。不把固定百分比或 8pt/24px 当系统中缝。
- 外屏竖版单栏；内屏横版左控制、右球道；半折 L 上画面、下控件。菜单/选关/皮肤中的拉杆仅为弱化的连续视觉，不暗示能在菜单内直接击球。
- 中缝只表现运河、峡谷或折痕过渡，绝不承载按钮、购买、确认、重开等交互。纯背景不得烘焙关键障碍或可交互内容。
- 动效只作为静态关键帧说明；一张图无法验证时长。真正动效由既有程序承担，不烘焙进一张长条图或假控件截图。

## 7. 拖入工程的顺序

1. 先把外部生成结果按主表/命名表存入 `/Users/cws/Desktop/FoldPutt/Resources/` 下对应目录。上述 VectorSources、AppIconSources 等是待导入目录清单，本轮只写文档，不创建这些目录或图片。
2. UI 概念图仅放 AIConcepts 供比对；导入 Xcode 时不勾 App target，避免将几十张宣传图打包进应用。它们不是可点击 UI，也不是验收截图。
3. 在现有 `Resources/Assets.xcassets` 内新建命名表指定的 Image Set，把 PDF/PNG/JPG 拖入正确槽。PDF 设 Single Scale + Preserve Vector Data；PNG 如选择 Single Scale，需要后续界面明确显示尺寸，1024 像素并不代表 1024pt。
4. 保留现有 `GolfBall`、`Flag`、`Star`、`CanalTile`、`AppIcon` 等资源；首次用 `FPArt…V001` 暂存。待视觉确认，再决定替换旧资产还是调整资源引用，不能静默覆盖。
5. 现有业务代码不会因为新 Image Set 的名字而自动引用它。本轮只提供命名/导入规范；实际接线或替换旧名称必须后续另行授权，不在此处改代码。
6. AppIcon 先检查确实没有 alpha，再经确认更新已有 AppIcon 资产。不要把原图和同名副本重复添加到两个 target 资源阶段。
7. 导入后用浅/深主题检查边缘、透明度和色差，用三态遮罩检查四边安全区与中缝。文字、按钮、拉杆、星级统计和物理规则继续由原生界面承担。
