# Q 版模式 · 小草坪俱乐部

2026-10-10。依据：用户明确授权把此前五个互动构思开发成开局可选模式，并增加三个细节。本次沿用现有 Swift + UIKit 工程；根 AGENTS.md 的历史「规划/空骨架」停点不适用于这次已授权开发。

## 怎么玩

启动后选择「普通模式」或「Q 版模式」。普通模式沿用现有草地素材，Q 版使用奶油纸色、鼠尾草绿、描边角色和短句手写字。两种模式都使用同一个单指拉杆：向后拖动，同时确定方向和力度，松手立即击球。

游戏内「设置与演示 → 切换游戏模式」可返回选择页。选择期间暂停同一局，切换后继续原球位、速度、杆数和关卡。未松手的拉杆会取消。Q 版菜单另有「小球心情」和「小球外观」，提供软乎乎 / 有点皮，以及糯米团子 / 桃桃丸子 / 芝麻小圆；全部直接可选。

## 八个小心思

| 细节 | 已实现的触发与表现 |
| --- | --- |
| 1. 表情小球 | 等待时微笑，瞄准时认真，滚动时轻轻转脸；草坪上的球保持实际碰撞半径，拉杆区同步放大表情，便于小屏看清。 |
| 2. 球杆挥击 | 拉杆距离带动球杆后撤；松手立即进入原有物理，球杆在击球原点做 0.24s 跟随挥击，不延迟出球。 |
| 3. 手写拟声词 | 击球「啵 / 走你！」、入沙「沙沙…」、入洞「咕噜」。使用系统楷体（不可用时回退），随 Dynamic Type 缩放；文字卡避开系统保留区。 |
| 4. 擦洞对视 | 小球先靠近洞口再远离时，洞口露出眼睛、小球侧目，出现「刚刚在叫我吗？ / 路过，路过。」每杆至多一次，正常入洞不会触发擦洞文案。 |
| 5. 入洞小卡 | 显示真实杆数和星数，糯米头像、奶油纸卡与下一关按钮。按心情及对局情况显示「到家啦。」「绕点远路，也到了。」「计划之内！」「终于下班了！」。 |
| 6. 蓄力鼓脸（新增） | 力度增长时脸颊逐渐鼓起；超过 72% 显示用力闭眼和汗滴，以及对应语气的小提醒。力度仍由原拉杆计算。 |
| 7. 碰撞懵脸（新增） | 真实障碍/河岸碰撞事件触发短暂叉叉眼与「叩 / 邦！」；0.45s 后表情恢复，不增加停顿、反弹或惩罚。 |
| 8. 场边观众（新增） | 纸边的小鸟和蘑菇在入洞后欢呼，动作在原有 0.8s 入洞反馈内完成。观众没有碰撞体；空间不足时省略装饰。 |

72% 阈值、擦洞距离和文案均为本轮设计实现建议，不是附件事实或新奖惩规则。

## 布局与状态

- 复用现有自适应容器与 `FPRegionSnapshot`。选择页以可滚动内容和原生按钮构成；由实际连续可用区域、horizontal/vertical size classes 与字号决定单列或双列。
- Q 版球道仍是现有关卡的几何投影；描边、沙纹、水纹、小花和观众不写入物理。原有中缝桥梁、障碍和镜头投影继续由既有适配逻辑处理。
- 只在 Q 版固定使用浅色画纸；切回普通模式恢复原有外观跟随。没有按设备名、姿态或 idiom 新增布局分支。
- 同一 scene 只创建一个 session。新增三个可选快照字段，旧版 v1 快照仍可读取，默认普通模式。恢复不会重播击球或成功奖励；结算仍可继续。
- 系统 Reduce Motion 开启时，取消转脸、挥杆跟随、观众跳动、粒子和镜头反馈，保留静态表情和文字。运行中系统通知会清理已开始的动效。音效/触感沿用独立开关。
- 视觉设计参考已交付的 `prototype/cozy-putt/`，原型仍是独立概念演示；本次截图为原生 UIKit 运行结果。

## 验证与证据

环境为 Xcode 27.1（27A9269）/ iOS 27.1 SDK。普通单屏使用 iPhone 16 Pro、iOS 18.5 模拟器；Duo 使用 Device Hub 的 iPhone Duo、iOS 27.1 模拟器。

- `work/q-mode/FinalPhone.xcresult`：34 个单元测试、普通模式真实拉杆与换关、Q 版开局选择 / 真实拉杆入洞 / 下一关通过。
- `work/q-mode/StandardUI.xcresult`：Q 版心情与外观菜单、保留同杆记录、切回普通模式通过。该次旧普通测试因依赖被大字号隐藏的状态标签而失败，后改为检查实际继续按钮，并以显式标准字号在 FinalPhone 中通过。失败结果保留供追溯。
- `work/q-mode/UI2.xcresult`：最大辅助字号的选择页滚动、Q 版拉杆/设置可达，以及 Reduce Motion 环境下完整 Q 版流程通过。对应截图的 `reduceMotion=true` 由实际诊断记录确认。
- `work/q-mode/Effects2.xcresult`：强蓄力、挥杆、擦洞、入沙、河岸碰撞五个原生截图夹具通过。夹具仅设置初始球位/输入，仍由实际物理或拉杆预览产生反馈。首次入沙检查暴露 DEBUG 诊断缓存未随纯表现事件更新，已把反馈序号加入诊断签名并通过复测。
- Release 模拟器构建通过（`work/q-mode/release.log`）。新增源码无 SwiftUI、Objective-C、`UIScreen.main` 或 `userInterfaceIdiom` 引用；未添加引擎或外部依赖。
- 每张有效截图的旁边保存 `*-layout.txt/json`，包含 bounds、traits、四边 safe area、division、occlusion、Reduce Motion 等。标准字号与大字号截图独立标注。
- Duo 展开横向内屏 951×669，traits=regular/regular，safe area 为 top=0、left=0、bottom=34、right=84；实测 division 为 `{{455.5,0},{40,669}}`，occlusion 为 `{{867,0},{84,120}}`。
- Duo 旋转后 669×951，top=82、bottom=34、左右=0；实测 inactive division 仍用于避让。Book 半折时系统激活横向 division，既有容器进入 handheld。三次诊断的按钮区域冲突列表均为空。

本轮未完成 Duo 合拢复测：操作 Device Hub 时 Mac 已锁屏，工具明确要求人工解锁，因此停止该部分 UI 操作。未验真机光学、握持、触觉、温度、完整 VoiceOver 导航或系统真实分屏。单屏完整可玩由 iOS 18.5 真正拉杆流程覆盖，不能替代 Duo 外屏验证。

## 文件入口

- `Models/FPGamePresentation.swift`：模式、外观、反馈事件去重、语气、动效令牌与调色板。
- `Views/FPModeSelectionController.swift`：选择页与同一 session 的容器切换。
- `Views/FPChibiArt.swift`：原生 Core Graphics 角色、场景、球杆与反馈绘制。
- `specs/q-mode.md`：交互约束与验收语义。
- `docs/screenshots/q-mode/`：有效原生截图与诊断；测试夹具画面以 `q-fixture-*` 标识。
