## 2. 这些语种是不是全部必需？

**不是。App Store Connect不要求按每个销售国家逐一增加当地语种，也不要求海外上架必须使用英文截图。** 英文可以作为商店基础语言，额外语言按目标用户选择；用户最终看到的元数据取决于店面、设备语言、已有本地化及主要语言。下表仅是后台语言映射，不是已经完成的App翻译，也不是已确定的销售国家名单。[苹果：商店信息本地化](https://developer.apple.com/help/app-store-connect/manage-app-information/localize-app-information/)

| 你的语言代码 | App Store Connect中选择的语言 | API/物料目录常用locale | 是否为上架硬性必需 | 本轮建议 |
| --- | --- | --- | --- | --- |
| 英文 | English (U.S.)；另可选English (U.K.)等 | `en-US` / `en-GB` | 不强制英文，但海外首发建议有一套完整英文 | 现有en-US可复制；新建App记录时建议主要语言选English (U.S.) |
| 土耳其语 `tr` | Turkish | `tr` | 否 | 想面向土耳其语用户展示本地文案时新增 |
| 阿拉伯语 `ar` | Arabic | `ar-SA` | 否 | 后台/API以ar-SA标识，不代表只能在沙特分发；App内RTL适配另做 |
| 葡萄牙语 `pt` | Portuguese (Portugal) / Portuguese (Brazil) | `pt-PT` / `pt-BR` | 否 | 按葡萄牙/巴西目标选择，不能用一个泛称pt代替后台两个变体 |
| 法语 `fr` | French / French (Canada) | `fr-FR` / `fr-CA` | 否 | 法国/法语一般用fr-FR；加拿大法语另有fr-CA |
| 西班牙语 `es` | Spanish (Spain) / Spanish (Mexico) | `es-ES` / `es-MX` | 否 | 西班牙选es-ES；墨西哥及相关西语店面按其支持映射选择es-MX，不等于自动勾选所有拉美国家 |

语言名与地区支持见[苹果语言/店面对照](https://developer.apple.com/help/app-store-connect/reference/app-information/app-store-localizations/)，locale短码见[苹果API对照](https://developer.apple.com/documentation/appstoreconnectapi/managing-metadata-in-your-app-by-using-locale-shortcodes)。不必机械地添加这五种语言；也不必为了阿语把当前未适配的App伪装成支持RTL。

这里的“非强制”仅说明App Store Connect的元数据机制；不替代特定市场对消费者信息、隐私或经营主体资料的适用要求。

### 三种设置分别控制什么

| 设置位置 | 控制的内容 | 当前处理 / 可复制说明 |
| --- | --- | --- |
| App Store Connect → Pricing and Availability | 哪些国家/地区可以买到或下载 | `仅选最终资料齐全的海外地区，暂不含中国大陆。` |
| App Store Connect → App Information及iOS版本页 → 语言 | 商店名称、描述、关键词、图片等 | `英文商店说明已准备；其他商店语言按市场选择添加。` |
| Xcode本地化资源、包内实际语言 | 安装后显示的App界面及相应语言能力 | `当前App界面支持zh-Hans、tr、ar、pt、fr、es；英文界面尚未提供。` |
| App Store Connect后台自身界面语言 | 你操作后台时看到的语言 | `可以继续用中文操作后台，不必为了海外商店改成英文后台。` |

苹果明确区分元数据本地化和Xcode二进制本地化；本轮声明实际的 `CFBundleLocalizations=[zh-Hans,tr,ar,pt,fr,es]`，六套资源均已入包，没有把英文等尚未翻译的语言加入声明。

### 主要语言怎么选

- 如果**还没有App记录**：新建时主要语言建议选择 `English (U.S.)`，使用现有en-US字段作为海外默认；可再增加简体中文元数据。App内采用已实现的六种语言，两者可以不同，但需如实列明支持范围。
- 如果**已有以中文为主要语言的记录**：先查看状态及允许编辑的字段，添加英文元数据。不要假设现有主语言一定能立刻改。苹果对变更主要语言有已添加、已审核及截图批准等条件，必要时先在本版提交英文，后续版本再变更。不要为改语言另建重复App或改Bundle ID。[主要语言变更条件](https://developer.apple.com/help/app-store-connect/manage-app-information/localize-app-information/#change-the-primary-language)

## 3. 除描述与截图，后台还需要哪些本地化字段？

这是**你主动新增一个商店语言时**要核对的字段，不表示每个销售国家都必须建立该语言。

| 字段 | 所在位置 | 每种已新增语言如何处理 / 可复制值 |
| --- | --- | --- |
| Name / 名称 | App Information | 品牌可全部保留 `FoldPutt`；后台核验可用性和权利 |
| Subtitle / 副标题 | App Information | 可选，最多30字符；使用该语言准确概括玩法，不承诺App已支持该语言 |
| Privacy Policy URL | App Information/App Privacy | 必需，可复用 `https://foldputt-help-wayne.humble-mite-6617.chatgpt.site/privacy`；简体中文可用中文页，无需每个语言新建域名 |
| Description / 描述 | iOS版本页 | 必需；新增语言时认真填写相应语言描述，如实列出已实现的六种App语言 |
| Keywords / 关键词 | iOS版本页 | 必需，≤100 UTF-8 bytes；新增语言需单独填写，不把中文关键词直接当成译文 |
| Promotional Text / 宣传文本 | iOS版本页 | 可选，≤170字符；如填写，翻译并核对长度 |
| Support URL | iOS版本页 | 必需，可复用 `https://foldputt-help-wayne.humble-mite-6617.chatgpt.site/support`；联系邮箱统一waynelessdo@gmail.com |
| Marketing URL | iOS版本页 | 可选，当前 `留空` |
| Screenshots / 截图 | iOS版本页/素材管理 | 至少满足所支持设备的要求；可继承主要语言图，建议有条件时提供真实对应语言界面图 |
| App Preview | iOS版本页/素材管理 | 可选，当前 `不上传`；以后按真实录像本地化 |
| What's New | iOS版本页 | 首版没有该项；后续更新必填，可按语言翻译 |
| Privacy Choices URL | 隐私信息 | 可选，无独立数据选择中心时 `留空` |
| 自定义EULA | 许可协议 | 当前采用 `Apple Standard EULA`，无需自己逐语种写一套自定义条款 |

新加本地化时，苹果通常默认沿用主要语言的截图和其他字段，**描述与关键词例外，需要补填**。这是一种默认/继承机制，不是“用英文填满所有语言就完成本地化”。字段依据：[版本字段](https://developer.apple.com/help/app-store-connect/reference/app-information/platform-version-information/)、[可本地化属性](https://developer.apple.com/help/app-store-connect/reference/app-information/required-localizable-and-editable-properties/)。

以下一般不需要为每种商店语言重复填：Bundle ID、SKU、构建、分类选择、版权主体、价格、销售地区、内容权利声明、年龄问卷和审核联系人。问卷回答按真实功能，Apple按其语言和店面显示结果。审核备注保留一份清晰英文即可；本项目无内购/订阅，不需要它们的多语言商品名称或说明。

### 现在的中文截图如何处理

可以使用现有真实中文UI截图，或本轮已验收的对应语言实图，英文描述列明六种实际语言；没有“非中文国家必须传英文UI图”的通用要求。当前也不应该把图里的中文按钮替换成英文来暗示正式App已提供英文。

若希望先改善英文商店展示，可以在真实截图外加英文宣传标题/操作解释，并保留真实UI及语言提示；这是宣传图层，不能代替真正的App本地化。Apple允许截图有解释性图文层，但要求准确反映App体验。[审核指南2.3及2.3.3](https://developer.apple.com/app-store/review/guidelines/#accurate-metadata)

本轮已实现并实际采集tr/ar/pt/fr/es界面。对应运行证据见项目docs/localization-20261022.md；现有商店元数据仍是en-US/zh-Hans，不会因App翻译自动生成五种商店译文。英文App界面尚未提供，不制作伪英文UI截图。

可直接放入英文描述/审核备注的提示：

```text

```

## 4. 从现在到实际公开上架，按顺序操作

### 步骤1：确定这次提交的语言范围

按用户新授权，当前App已有中文及tr/ar/pt/fr/es界面，英文商店说明已同步；五种语言的商店元数据仍可按目标市场另行添加。若希望首发安装后就显示英文，需先完成App内英文再提审；仅换商店文案不能实现。

可复制记录：

```text
本次构建界面：zh-Hans、tr、ar、pt、fr、es；商店元数据：en-US及zh-Hans；英文App界面：未提供；截图：真实对应当前构建。
```

### 步骤2：准备受支持的正式Xcode

本机仍是Xcode27.1 `27A9269` beta。使用Apple已接受、且提供当前Duo API的正式27.1或兼容的后续正式工具链重建。先核对 `xcodebuild -version`；上一轮官方正式27.1记录为 `27A9275`，具体接受状态提交前再核对。不要用旧SDK绕过Duo能力。

可复制记录：`Xcode：【正式版本/build】；SDK：【值】；Apple接受状态：【已核对】。`

### 步骤3：登录正确账号并核对Team

在Xcode → Settings → Accounts中使用本人 Apple Account 登录；App Store Connect中选同一发布Team，核对有效会员、协议和角色。账号邮箱与对外邮箱不同是正常情况，网站不会修改登录账号。需要接受新协议或做身份验证时由账号持有人在官方流程完成。

可复制记录：`Team：【实际名称/ID】；会员：【有效状态】；协议：【状态】；发布角色：【实际角色】。`

### 步骤4：核对App ID与App记录

Developer账号下确认显式App ID `com.mavericklab.foldputt` 属于本Team；已有App则复用。若该ID无法归属当前Team，先处理真实ID与工程一致性，再上传，不能只在后台随便选另一个ID。

尚无记录时，App Store Connect → Apps → + → New App：Platform=iOS，Name=FoldPutt，建议Primary Language=English (U.S.)，Bundle ID与工程一致，SKU可用foldputt-ios-202610。已有SKU/记录沿用。

可复制记录：`App Apple ID：【自动生成值】；Bundle ID：com.mavericklab.foldputt；版本：0.2.0；主要语言：【后台实际值】。`

### 步骤5：核对签名、版本与设备家族

Xcode Target → Signing & Capabilities选择真实发布Team，按实际证书/Provisioning Profile完成签名。保留iPhone+iPad、最低18.0及Duo，确认新联系方式的政策和隐私清单入包。版本当前0.2.0/build1；若后台已用build1，只递增构建号并重建。

可复制记录：`版本0.2.0（【实际build】）；UIDeviceFamily=[1,2]；签名Team【值】；包内隐私与Gmail联系方式已核对。`

### 步骤6：生成可分发Archive并上传

选择Any iOS Device/通用设备目标 → Product → Archive；Organizer选择此次Archive，按正式工具链可用操作执行Validate App及Distribute App → App Store Connect → Upload。当前work中的unsigned archive仅用于构建和包内容核查，不能直接替代正式签名分发包。

可复制记录：`正式Archive：【位置】；签名/验证：【结果】；上传版本/build：【值】；上传时间：【北京时间】。`

### 步骤7：等待构建处理，核对合规并做分发安装验证

后台处理完成后，在iOS版本的Build区选择正确构建。当前包 `ITSAppUsesNonExemptEncryption=false`；出现合规问题时按具体问法和真实加密行为回答，不能所有题统一填No。建议用TestFlight安装真正的分发包，至少验证iPhone/iPad的开局、拖杆、入洞、换关、收藏、隐私入口与存档；Duo可用时补实际设备验收。

可复制记录：`处理构建：【版本/build】；出口合规：【结果】；TestFlight安装及关键流程：【环境/结果】。`

### 步骤8：填商店文案、URL和图片

使用本目录的App-Store-Connect-填写清单.md和app-store/metadata/en-US/中的独立文本；需要中文时添加zh-Hans。填写下面真实URL，按设备槽上传现有iPhone/iPad/Duo图，勿把iPad图拉伸成Duo图。没有Preview可以留空；版权2026 Wayne。

### 步骤9：完成隐私、年龄、权利与审核资料

App Privacy按当前无运行时数据上传等真实实现填写；年龄问卷由后台计算；资源权利按asset-provenance.md与真实授权确认。App Review Information填真实联系人姓、名、可接通国际电话及Gmail；无需登录，演示账号留空，英文Notes直接复制已有文件。Wayne不能擅自拆成尚未提供的法定姓/名。

可复制记录：`隐私标签：【结果】；年龄评级：【结果】；内容权利：【证据】；审核联系人：【真实姓/名/电话】；Email：waynelessdo@gmail.com；Sign-in required：No。`

### 步骤10：选择免费和具体国家/地区

Price=Free。当前确定不含中国大陆；tr/ar/pt/fr/es是语言，不是完整国家清单，需逐个勾选实际目标地区。选择法国/葡萄牙/西班牙等欧盟地区前完成真实DSA身份声明与适用验证；没有相应许可的市场先不选。不要直接“全球全选”。Mac和Vision兼容分发暂不扩大到未验收平台。

可复制记录：`Price：Free；首发国家/地区：【明确列表】；中国大陆：不选择；DSA/适用地区资料：【状态】；发布方式：Manually release this version。`

### 步骤11：正式发送审核

全部必填字段与构建就绪后，版本页点 **Add for Review**，再进入草稿/App Review点 **Submit for Review**。前一个按钮只是加入审核草稿，不表示已经送审。核对实际状态进入Waiting for Review/In Review；加急可申请但不保证受理、通过或时间。[苹果提交流程](https://developer.apple.com/help/app-store-connect/manage-submissions-to-app-review/submit-an-app)

可复制记录：`提交版本/build：【值】；Submit for Review时间：【北京时间】；后台状态：【真实值】。`

### 步骤12：审核通过后发布并验证下载

建议采用手动发布；获批后确认实际授权，再在Pending Developer Release执行发布。到目标店面核对名称、英文/已添加语言、截图、年龄和政策/支持链接，并实际安装。审核和传播耗时不能用Duo开售日替代，不能保证10月23日某时可下载。

可复制记录：`批准状态：【值】；公开发布时间：【北京时间】；店面：【地区】；App Store真实链接：【值】；实际下载验证：【结果】。`
